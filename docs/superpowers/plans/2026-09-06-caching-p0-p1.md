# PostgreSQL-first optimization and conditional Redis pilot

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Reduce measured repeated read work without changing financial results, durable PostgreSQL truth, or Kafka/outbox delivery.

**Architecture:** Bound PostgreSQL history reads with indexed lateral top-N queries; share portfolio valuation in a combined authenticated view; enforce leaderboard visibility from committed database state. Establish a new baseline before choosing any optional, isolated Redis computation-cache pilot. No production Redis deployment.

**Tech stack:** FastAPI/SQLModel/PostgreSQL, Next.js, pytest/Vitest, optional local Redis only if P0 evidence supports a pilot.

## Acceptance

No result mismatch; no privacy reliance on process-local invalidation; no financial float conversion; no production/provider changes. Redis must show incremental benefit over P0, remain disabled by default and disposable, and never become a normal-read dependency. Latency is local evidence, not production projection; DB cursor wall time and application thread CPU are reported separately.
